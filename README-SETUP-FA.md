# راه‌اندازی نسخه جدید Personal OS روی GitHub Pages

این بسته شامل رابط بازطراحی‌شده، فایل SQL پایگاه داده و همین راهنمای نصب است.

## محتویات بسته

- `index.html` — فایل اصلی برنامه؛ همین فایل را جایگزین `index.html` فعلی مخزن GitHub کن.
- `supabase-setup.sql` — ساخت جدول امن و قوانین دسترسی و فعال‌سازی Realtime.
- `README-SETUP-FA.md` — راهنمای راه‌اندازی.

## چه چیزهایی تغییر کرده؟

- ظاهر برنامه با حفظ بخش‌ها و امکانات قبلی، به سبک مینیمال‌تر و حرفه‌ای‌تر بازطراحی شده است.
- واکنش‌گرایی صفحه برای موبایل، تبلت و دسکتاپ بهبود یافته است.
- تنظیمات فعلی فونت، رنگ، قالب، پس‌زمینه، اندازه متن و حالت فشرده حفظ شده‌اند.
- اتصال ابری Supabase اضافه شده است. داده‌ها پیش از ارسال با رمز اصلی برنامه رمزگذاری می‌شوند.
- دریافت تغییرات دستگاه‌های دیگر از طریق Supabase Realtime انجام می‌شود و ذخیره‌سازی با شماره نسخه برای کاهش احتمال بازنویسی هم‌زمان محافظت شده است.
- نسخه محلی رمزگذاری‌شده و امکان خروجی گرفتن از اطلاعات همچنان باقی است.

## مرحله ۱ — ساخت پروژه Supabase

1. وارد `https://supabase.com` شو و یک پروژه جدید بساز.
2. پس از آماده شدن پروژه، از بخش **Project Settings → API** آدرس پروژه و کلید عمومی را بردار.
3. فقط از **anon / publishable key** استفاده کن. کلید `service_role` یا هر کلید محرمانه‌ای را هرگز در HTML، GitHub یا مرورگر قرار نده.
4. در بخش **Authentication → Providers → Email** ورود با ایمیل را فعال نگه دار.
5. در **Authentication → URL Configuration**، آدرس سایت GitHub Pages خودت را به‌عنوان Site URL ثبت کن؛ نمونه: `https://USERNAME.github.io/REPOSITORY/`.

## مرحله ۲ — ساخت جدول و مجوزها

1. در داشبورد Supabase وارد **SQL Editor** شو.
2. فایل `supabase-setup.sql` را باز کن و تمام محتوایش را اجرا کن.
3. اجرای موفق باید جدول `personal_os_vaults` را بسازد.
4. این جدول فقط برای کاربر واردشده و فقط برای ردیف متعلق به همان حساب قابل دسترسی است؛ این محدودیت با Row Level Security اعمال می‌شود.

## مرحله ۳ — انتشار فایل در GitHub

1. از نسخه فعلی مخزن خودت یک نسخه پشتیبان نگه دار.
2. فایل `index.html` داخل این بسته را در ریشه مخزن GitHub بارگذاری کن و نسخه قبلی را جایگزین کن.
3. اگر GitHub Pages هنوز فعال نیست، در **Settings → Pages** انتشار از شاخه موردنظر و پوشه ریشه را فعال کن.
4. سایت را با آدرس HTTPS باز کن. قفل رمزگذاری برنامه به HTTPS نیاز دارد.

## مرحله ۴ — اتصال دستگاه اول

1. برنامه را باز کن و با رمز اصلی خودت وارد شو.
2. وارد **تنظیمات → امنیت و همگام‌سازی** شو.
3. آدرس پروژه، کلید عمومی، ایمیل حساب Supabase و رمز حساب را وارد کن.
4. اگر حساب نداری، «ساخت حساب جدید» را انتخاب کن. در صورت فعال بودن تأیید ایمیل، ایمیل را تأیید کن و سپس با حالت «ورود به حساب موجود» دوباره وارد شو.
5. در قسمت «رمز اصلی اطلاعات»، همان رمز قفل Personal OS را وارد کن.
6. روی «اتصال و همگام‌سازی» بزن.

اگر جدول ابری هنوز اطلاعاتی نداشته باشد، داده‌های رمزگذاری‌شده همین دستگاه به ابر منتقل می‌شوند. اگر از قبل اطلاعات ابری وجود داشته باشد، برنامه آن‌ها را با رمز اصلی باز می‌کند و با داده‌های محلی ادغام می‌کند.

## مرحله ۵ — اتصال دستگاه‌های دیگر

1. همان آدرس سایت را روی دستگاه دوم باز کن.
2. اگر اولین بار است، برای قفل محلی برنامه همان رمز اصلی را انتخاب کن.
3. به تنظیمات همگام‌سازی برو و همان آدرس پروژه، کلید عمومی، ایمیل و رمز حساب Supabase را وارد کن.
4. رمز اصلی اطلاعات باید دقیقاً همان رمز اصلی دستگاه اول باشد.
5. اتصال را انجام بده. برنامه نسخه ابری را دریافت می‌کند و پس از آن تغییرات را از طریق Realtime دریافت خواهد کرد.

## نکات مهم امنیت و نگهداری

- رمز اصلی Personal OS با رمز حساب Supabase یکی نیست؛ این دو را با هم اشتباه نگیر.
- رمز اصلی را فراموش نکن. اطلاعات ابری به‌صورت رمزگذاری‌شده ذخیره می‌شوند و بدون رمز اصلی قابل بازیابی نیستند.
- کلید عمومی Supabase در مرورگر استفاده می‌شود و به‌تنهایی مجوز دسترسی به اطلاعات دیگران را نمی‌دهد؛ امنیت داده‌ها به قوانین RLS وابسته است. فایل SQL این قوانین را ایجاد می‌کند.
- کلید `service_role` را در هیچ بخشی از برنامه قرار نده.
- هنگام تغییر هم‌زمان یک مجموعه داده (مثلاً ویرایش یک لیست واحد) از دو دستگاه، برنامه از شماره نسخه و ادغام داده‌ها استفاده می‌کند؛ با این حال بهتر است ویرایش یک مورد مشخص را هم‌زمان روی دو دستگاه انجام ندهی.
- اگر رمز اصلی برنامه را تغییر بدهی، رمزگذاری ابر نیز با رمز جدید به‌روزرسانی می‌شود. در دستگاه‌های دیگر باید با رمز جدید دوباره اتصال را تأیید کنی.
- «قطع اتصال این دستگاه» فقط اتصال همان دستگاه را قطع می‌کند و ردیف ابری را حذف نمی‌کند.
- علاوه بر همگام‌سازی، هر چند وقت یک بار از بخش پشتیبان‌گیری خروجی بگیر.

## نکته درباره نسخه فعلی

نسخه قبلی از یک مخزن خصوصی GitHub برای همگام‌سازی استفاده می‌کرد. در این نسخه، Supabase مسیر پیشنهادی همگام‌سازی است. اگر قبلاً GitHub Sync را فعال کرده‌ای، قبل از تغییر سرویس یک خروجی پشتیبان رمزگذاری‌شده بگیر و پس از اتصال Supabase، روی دستگاه‌های دیگر نیز ورود و دریافت اطلاعات را بررسی کن.

## وضعیت دستیار هوش مصنوعی

بخش دستیار هوش مصنوعی در کد اصلی به محیط اجرایی Claude وابسته است (`window.claude.use`). این محیط در GitHub Pages به‌صورت خودکار وجود ندارد؛ بنابراین این بسته ظاهر و داده‌های آن بخش را حفظ می‌کند، اما فعال‌سازی درخواست‌های AI روی GitHub Pages را ادعا نمی‌کند. برای فعال‌سازی امن آن باید یک سرویس سمت سرور یا Edge Function به مدل هوش مصنوعی متصل شود؛ کلید API مدل نباید در HTML قرار بگیرد.
